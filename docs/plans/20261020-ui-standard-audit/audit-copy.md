## Inventory and method

[audit-interpolations.md](audit-interpolations.md) indexes **425 catalog messages and 565 key/parameter pairs**, including `count` used only to select a plural form, with **382 literal references** in production UI source. [audit-interpolations.json](audit-interpolations.json) preserves each English message, English/Chinese catalog location, parameter classification, reference context, narrow dynamic render routes and **123 dynamic translation expressions**. A declaration/type argument is identified as a reference, not misrepresented as an actual render. Every catalog parameter has a classification and its applicable rule; the findings below give the exceptional render scopes.

The extraction walked the TypeScript syntax tree of `packages/ui/src`, excluding tests, gallery source and test helpers from the catalog-reference population. It read object-valued plural messages as well as string messages, adding implicit `count`; a grep only for braces would miss twelve messages and fifteen parameter pairs. Literal references include `createElement(Message<...>, ...)`, nested `Message`, message-key tables, and calls to `t`/`format`. Narrow union types resolve dynamic IDs without guessing from the variable name. The JSON separately lists every dynamic expression, including those whose broad `PlainMessageKey` type does not identify its concrete table. Those routes are accounted for below. The two checked-in translated catalogs use the same schema; `ar` changes layout direction and currently falls back to English text.

These classifications are deliberately contextual:

- Counts, percentages, timestamps, duration fragments and ordinary prose are not quoted names. No chip is required solely because they pass through an interpolation. A fixed-order numeric ratio still needs left-to-right rendering.
- The global `appName` is ordinary application branding. An `agent` parameter needs a caller-level decision: a plain accessible label or whole agent choice stays text, but a named agent referenced inside a visible title, sentence or control label is a name-in-copy surface (COPY-09). Fixed membership in AGENT_LABEL is not an exemption from that rule.
- Accessible names, `textValue`, native menus, system notifications, input values and placeholders are plain-text surfaces. They cannot receive chip markup. Isolate a substituted value in a sentence, except in `textValue`/sorting/matching or a whole value already in an element with direction.
- A visible tooltip is React content in this application (`IndicatorTooltip`, `AnchoredTooltip`, `TitledControl`); its accessibility label is a separate plain string. A shared helper returning a string is not a reason to omit chips from its rich visible tooltip.
- Structured path rows, file/directory names in collections, the viewer's primary path, source/Markdown/terminal output, and repository examples displayed as source retain their own renderers. They are not application prose that should be wrapped in a chip wholesale.

## Checks that are already sound in source

The shared `InlineChip` preserves a code child for technical values and defaults those to `dir="ltr"`; inherited-size roles are used throughout StartupScreen, trust paths, confirmation words, account-login code, import paths and ordinary confirmation names. `TrustPromptDialog` uses chips for the path/session/directory, not a CodeBlock for a single path. `SessionRequestDialog` uses localized placeholders and `joinNodes` for all requester/console/project/session names and transferred branches. `SwitchAccountDialog` separates rich current-session display from its plain live progress announcement. Import review/results separate rich setting/name/path copy from plain announcements. Account collision validation likewise has separate plain and rich forms. `DaemonErrorMessage` keeps raw structured branch-cleanup diagnostics in CodeBlock through BranchGroups. These are reusable implementation patterns, not unverified visual passes.

Approved exceptions are preserved: ordinary library styles below custom thresholds are outside this source finding set; entity rows and paths retain their dedicated layout; raw matching/textValue is not isolated; system notifications remain text; stock Alert title, description, indicator, spacing and typography must survive every proposed migration.
