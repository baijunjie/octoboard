{/* How the Linux server program is uninstalled, which the Linux server guide and "Your system stays as it was" share. */}

Выполните на сервере эту команду от имени пользователя, для которого он был установлен. Ничего не загружается.

<Code code={system.uninstall} lang="sh" />

Сначала она перечисляет всё, что собирается сделать, и просит ввести <code dir="ltr">{system.uninstallWord}</code>. <code dir="ltr">{system.uninstallDryRun}</code> только показывает этот список, а <code dir="ltr">{system.uninstallYes}</code> подтверждает там, где нет терминала, в котором можно спросить.

Затем она выключает общий доступ для каждого аккаунта, который всё ещё делится конфигурацией по умолчанию. Для этого она останавливает службу, если та работает, что завершает все сеансы, которые служба выполняет, и запускает её только для этой очистки, без сеансов. После этого она останавливает службу и удаляет программу вместе с её службой systemd, если она есть, а также выключает lingering, если его включила установка службы и он не нужен другим вашим службам.

- <strong>Если аккаунт не может перестать делиться</strong>, например потому что один из его сеансов работает, ничего не удаляется, а служба запускается снова так, как работала: выполните команду ещё раз, когда эта работа закончится. С <code dir="ltr">{system.uninstallKeepChanges}</code> она удаляет программу без этой очистки и оставляет ссылки в папке каждого такого аккаунта, а рядом с ними резервные копии собственной конфигурации аккаунта, чтобы вы удалили их вручную.
- <strong>Если остановка службы прервёт работу</strong>, ничего не удаляется. <code dir="ltr">{system.uninstallForce}</code> всё равно останавливает её.
- <strong>Запускайте тот <code dir="ltr">{system.cliName}</code>, который вы установили.</strong> Запущенная через ссылку или из другой копии <code dir="ltr">{system.cliName}</code>, чем та, которую выполняет служба {productName}, она ничего не удаляет и называет файл, который нужно запустить вместо этого.

Прежняя команда установочного скрипта по-прежнему работает и запускает эту. Если вы устанавливали с <code dir="ltr">{system.binDirOption}</code>, добавьте его с той же папкой.

<Code code={system.uninstallScript} lang="sh" />

Если ваш <code dir="ltr">{system.cliName}</code> слишком старый и не знает команды удаления, команда скрипта удаляет его сама, но ничего не выключает заранее: аккаунт, который всё ещё делится конфигурацией по умолчанию, сохраняет ссылки в своей папке, их можно удалить вручную.
