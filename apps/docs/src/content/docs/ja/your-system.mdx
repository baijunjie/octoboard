{productName} は、お使いのシステムを元のままにします。エージェントの設定も、{productName} 自身のフォルダの外にあるものもすべてです。ただし、いくつかの機能は、そのフォルダの外に何かを追加します。このページでは、それらをすべて挙げ、何をどこに追加するのか、どうすれば元に戻せるのかを説明し、アンインストール後に何が残るのかも説明します。

## ルール

- <strong>{productName} がエージェントに渡すものは、起動のたびに、その起動にだけ渡されます。</strong> ステータス用のフック、{productName} 自身の MCP サーバー、セッションに伝える役割は、エージェントの起動時に渡されるか、{productName} 自身のフォルダに置かれます。そのためにあなたのファイルやエージェントのファイルが編集されることはないので、エージェントを単独で実行すれば、これらは一切ない状態で起動します。
- <strong>{productName} は、あなたの設定に自分のフックを追加せず、プロジェクトのフォルダについてあなたに代わって何かを決めることもありません。</strong> プロジェクトのフォルダを信頼するかどうかは、あなたが決め、エージェントが記録します。{productName} が答えるのは、コンソール自身のフォルダだけです。これは {productName} のフォルダだからです（後述）。
- <strong>エージェントが自分のために書き込むものは、エージェントのものです。</strong> 会話の記録、キャッシュやログ、ログインの認証情報、エージェント自身の確認に答えたときに記録される信頼は、{productName} を使わずにエージェントを使うときと同じように書き込まれます。エージェント自身のプログラムが、ある設定フォルダで初めて動くときに行う初期設定も同じです。{productName} がバックグラウンドで情報を読み取ると、あなた自身の最初の起動より前にこれが行われることがあります（後述）。
- <strong>プロジェクトの中での作業は、このページの対象ではありません。</strong> プロジェクトのファイルの編集、Git の操作、ブランチやワークツリーは、プロジェクトを追加して行う開発作業そのものです。

## 機能が追加するものと、元に戻す方法

以下はいずれも、あなたが使うか、オンにした機能によってのみ追加されます。

### 機能をオフにすると元に戻るもの

- <strong>リモートサーバー上の、このコンピューターの鍵。</strong> 保存済みのリモートデーモンにパスワードまたは鍵ファイルでサインインしたあと、アプリは何かを追加する前に確認します。<strong>このコンピューターの鍵を追加</strong>というダイアログに、どのファイルのどの行かが示されます。<strong>鍵を追加</strong>を選ぶと、そのサーバーのあなたのユーザーの、許可する SSH 鍵の一覧（Linux と macOS では <code dir="ltr">{commands.authorizedKeys}</code>）に、<code dir="ltr">{system.keyMark}</code> という目印の付いた 1 行が追加され、秘密鍵はこのコンピューターの資格情報ストア（macOS ではログインキーチェーン、Windows では資格情報マネージャー）に保管されます。<strong>追加しない</strong>を選ぶと何も追加されず、以後は確認されません。元に戻すには、<strong>リモートデバイス</strong>にあるそのデーモンのページで<strong>このコンピューターの鍵</strong>をオフにするか、保存済みのデーモンを取り除きます。アプリがその行をファイルから削除し、秘密鍵も削除します。保存済みのデーモンのホスト、ポート、ユーザーを変更したときも同じです。サーバーに接続できない場合は、その行が残ることがあり、アプリがそれを知らせるので、サーバー上で自分で削除してください。
- <strong>ログイン時に開く</strong>（Windows、および macOS 13 以降）。<strong>設定 › 一般 › ログイン時に開く</strong>をオンにすると、システムがログイン時に開くアプリの一覧に {productName} が加わります。この行の説明にもそう書かれています。その一覧から外すには、このスイッチをオフにします。
- <strong>コマンドラインツール</strong>（macOS）。<strong>設定 › 一般 › コマンドラインツール</strong>で<strong>インストール</strong>を選ぶと、<code dir="ltr">{system.cliDir}</code> に <code dir="ltr">{system.cliName}</code> という名前のリンクが追加されます。システムがそれを許可しない場合は <code dir="ltr">{system.cliFallbackDir}</code> に追加されます。インストールする前から、この行にそう書かれています。<strong>削除</strong>を選ぶと、そのリンクが削除されます。
- <strong>デフォルト構成の共有。</strong> <strong>設定 › アカウント</strong>にあるアカウントの設定の<strong>デフォルト構成を共有</strong>をオンにすると、そのアカウントのフォルダのうち共有できる部分がデフォルトアカウントのフォルダへのリンクに置き換えられ、アカウント自身の構成はバックアップとしてその横に残され、会話履歴はデフォルトアカウントのフォルダに移されます。オンにする前から、この行にそう書かれています。オフにすると、リンクが取り除かれ、バックアップが元に戻され、そのアカウント自身のセッションの会話が戻されます。<strong>1 つだけ残るものがあります。</strong> 移された会話履歴の残りは、デフォルトアカウントのフォルダに残ります。取り除くとあなたの会話が失われてしまうためです。[Shared configuration](../features/shared-configuration/) を参照してください。

### あなたやエージェントのものとして残るもの

以下で書き込まれるものは、それ以降あなたのもの、またはエージェント自身のものになるので、{productName} が自分のものとして元に戻すものはありません。手作業で削除できるエントリについては、その場所を項目の中で示します。

- <strong>セッションのアカウントの切り替え。</strong> <strong>アカウントを切り替え</strong>は、実行する前に確認を求めます。エージェントが求めた切り替えは、<strong>アカウントの切り替えを自動で承認</strong>をオンにしていないかぎり、あなたの承認を待ちます。使用制限に達したときの切り替えは、<strong>使用制限に達したらアカウントを自動で切り替え</strong>がオンの間だけ行われます。切り替えでは、そのセッション 1 つの会話が、切り替え先のアカウントのフォルダにコピーされます。Codex の場合は、そのアカウント自身が持つこの会話の記録も、コピーを指すように書き換えられます。元の会話は元の場所に残り、コピーはそのアカウント自身のものとして残ります。[Account continuity](../features/account-continuity/) を参照してください。
- <strong>Grok Build のセッションの中で変更した設定とプラグイン。</strong> あなたの <code dir="ltr">config.toml</code> がファイルへのリンクである場合、セッションの中で変更したテーマ、プラグインのオン・オフ、デフォルトのモデルは、セッションの終了時に、Grok 自身が保存するのと同じようにそのファイルに書き込まれます。セッションの中でインストールしたプラグインは、あなたの Grok フォルダ自身のプラグインレジストリがあれば、そこに記録されます。
- <strong>プロジェクトのフォルダに対する Grok Build の信頼。</strong> プロジェクトのフォルダを信頼することにあなたが同意すると（<strong>信頼して続行</strong>を選ぶか、ターミナルで自分で答えると）、Grok が書き込んだ 1 つのエントリが、そのまま、あなたの Grok フォルダの信頼リストに移されます。
- <strong>一度も会話のなかったセッションの記録。</strong> 何も送ったことのないセッションを削除すると、エージェント自身が持つそのセッションの記録も、確認なしで一緒にゴミ箱（Windows ではごみ箱）に移されます。そこにはあなたの会話が含まれていないためです。使ったことのあるセッションの記録は、確認ダイアログでそのオプションにチェックを入れた場合にだけ移されます。記録はゴミ箱から元に戻せます。
- <strong>Claude Code の初回起動時の設定。</strong> Claude Code がまだ一度も動いたことのない設定フォルダでは、または Claude Code のアップデート後には、{productName} によるバックグラウンドでの読み取り（アカウントの使用量、MCP サーバー、エージェント）によって、Claude Code 自身の初回起動時の設定と保留中の移行がそこで行われます。これは、次にあなたが起動したときに行われたはずのものと同じです。{productName} はその変更をそのままにします。
- <strong>新しい Codex アカウント用の空のフォルダ。</strong> Codex アカウントの最初の起動またはサインインの前に、そのアカウントのフォルダがまだなければ、{productName} が空のフォルダを作ります。これがないと Codex は起動を拒否するためです。
- <strong>コンソール自身のフォルダに対する信頼。</strong> コンソールセッションは {productName} 自身のフォルダで動くので、そこでエージェントが信頼するかどうかを尋ねると、{productName} はあなたに尋ねずに答えます。そのあと Claude Code は、自分の信頼リストに、そのフォルダだけを指すエントリを残します。ほかの場所には何の影響もありません。Codex は、そのフォルダが Git リポジトリの中にある場合にだけ尋ね、そのリポジトリのルートに対して信頼を記録します。この記録はリポジトリ全体に及びます。ホームフォルダを Git で管理している場合は、ホームフォルダ全体です。Grok Build は、あなたの信頼リストに何も記録しません。{productName} はこれらのエントリを削除しません。削除すれば、あなたのファイルをもう一度編集することになるためです。自分で削除することはできます。Codex のエントリは、Codex のフォルダにある <code dir="ltr">config.toml</code> の <code dir="ltr">[projects."&lt;repository root&gt;"]</code> テーブルで、Claude Code のエントリは、<code dir="ltr">.claude.json</code> の <code dir="ltr">projects</code> の下にある、そのフォルダのエントリです。

### アンインストールコマンドで元に戻すもの

- <strong>サービスとして動かす Linux サーバー用プログラム。</strong> サービスとしてインストールすると（[Linux サーバー](../install/linux/) を参照）、あなたの systemd の設定フォルダに systemd のユーザーサービスが書き込まれ、あなたのユーザーの lingering がオフだった場合はオンになります。これを元に戻すには、あとで示すアンインストールコマンドを使います。

<Aside>
Windows では、アプリはタスクバーのボタンのジャンプリストも保持していて、そこには保存済みのリモートデーモンが並びます。これにはスイッチがありません。あとで説明する<strong>すべて削除</strong>がこれを削除し、アンインストーラーも削除します。
</Aside>

## アンインストールする前に

アンインストールする前に、「機能をオフにすると元に戻るもの」のうち現在有効なものをすべてまとめて削除し、それぞれの機能をオフにできます。デスクトップアプリでは、<strong>設定 › クリーンアップ</strong>にそのための行<strong>アンインストール前のクリーンアップ</strong>が 1 つあります。有効な項目がいくつあるかが示され、ボタンは<strong>すべて削除</strong>Windows ではアンインストーラーも自分でこれを行い、Linux サーバー用プログラムのアンインストールコマンドは最初にこれを行います。どちらもあとで説明します。

- <strong>先に確認を求めます。</strong> 確認のダイアログには、削除される項目の数（一覧はその数の下に折りたたまれています）と、何が残されるかが示されます。<strong>削除</strong>と入力するまで先へ進みません。
- <strong>結果を表示します。</strong> 終わると、削除されたものと削除されなかったものが示されます。接続できないサーバー上の鍵など、削除できなかった項目については、何がどこに残っているかが示されます。
- <strong>そのコンピューター上の、アプリ自身のウィンドウにだけあります。</strong>デスクトップアプリのあるコンピューターのブラウザや、リモートのデーモンを表示しているウィンドウでは、この行にはクリーンアップをどこで行うかだけが書かれています。ブラウザで Linux サーバーを開いている場合は、サーバー上でのアンインストールが最初にクリーンアップを行うことが書かれ、サーバー上で実行できるよう、<code dir="ltr">{system.uninstall}</code> が<strong>アンインストールコマンドをコピー</strong>とともに表示されます。そこからは何も削除されません。
- <strong>アンインストールするときにだけ使います。</strong> 1 つだけを元に戻して {productName} を使い続ける場合は、代わりにその機能をオフにしてください。
- <strong>あなたのデータは残します。</strong> {productName} 自身のフォルダは残り、共有によって移された会話履歴も残ります。

### 残るもの

{productName} 自身のフォルダは残るので、あとでインストールし直すと、コンソール、セッション、設定がそのまま使えます。これらも削除したい場合は、フォルダを削除してください。コンソール、セッションの記録、設定はすべて失われます。

- <strong>データフォルダ</strong>（セッションを動かしていたコンピューターまたはサーバーにあります）: <code dir="ltr">{system.dataDir}</code>（Windows では <code dir="ltr">{system.dataDirWindows}</code>）。macOS と Linux では、<code dir="ltr">{system.removeDataDir}</code> で削除できます。
- <strong>デスクトップアプリ自身のフォルダ:</strong> macOS では <code dir="ltr">{system.appDataMac}</code>、Windows では <code dir="ltr">{system.appDataWindows}</code> と <code dir="ltr">{system.appLocalDataWindows}</code>。

エージェント自身のフォルダは、ログイン、設定、会話も含めてエージェントのものであり、そのまま残ります。
