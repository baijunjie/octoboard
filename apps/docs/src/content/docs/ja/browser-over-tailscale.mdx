自分の Tailscale ネットワークを通して、別のコンピューターのブラウザで {productName} を開きます。SSH もリモートデスクトップも使いません。ホストとは {productName} が動いているコンピューターのことで、Mac、Windows PC、または octoboardd を動かしている Linux サーバーです。SSH ログイン（macOS ではリモートログイン）はオフのままで構いません。

この方法が自分に合っているかわからない場合は、[接続方法を選ぶ](../choose-how-to-connect/)をご覧ください。

<Aside type="caution">
この手順は、まだ十分にテストできていません。Tailscale Serve のドキュメントと、{productName} 自身の確認に基づいています。中継プログラムは 1 台のコンピューターで試していて、ブラウザのライブ接続も含めて確認済みですが、2 台のデバイスの間での Tailscale Serve と、Windows のフォワードは、まだ試していません。
</Aside>

<strong>自分のコンピューターのブラウザ</strong> → <strong>自分のコンピューターの中継（127.0.0.1）</strong> ⟷ Tailscale ⟷ <strong>ホストのブラウザ用ポート（127.0.0.1）</strong> → <strong>{productName}</strong>

<details>
<summary>はじめての方へ</summary>

- <strong>Tailscale:</strong> 自分のデバイスを、どこにあってもインターネット越しに 1 つのプライベートなネットワークにつなぐサービスです。自分のアカウントでサインインして使います。
- <strong>Tailnet:</strong> 自分の Tailscale ネットワークのことで、自分の Tailscale アカウントにサインインしているデバイスの集まりです。
- <strong>127.0.0.1（ループバック）:</strong> 常に「このコンピューター自身」を指すアドレスです。
- <strong>ポート:</strong> コンピューター上の 1 つのプログラムを選ぶための番号で、部屋番号のようなものです。<code dir="ltr">127.0.0.1:{commands.defaultPort}</code> は、このコンピューターのポート {commands.defaultPort} を指します。
- <strong>socat:</strong> 接続をある場所から別の場所へ受け渡す、小さな無料のプログラムです。ここでは中継の役目をします。
- <strong>Tailscale Serve:</strong> ポートを自分の tailnet の中だけに共有する Tailscale のコマンドです。似た機能の Tailscale Funnel はインターネット全体に共有してしまうので、ここでは絶対に使わないでください。
- <strong>ターミナル:</strong> コマンドを入力するウィンドウです。macOS ではターミナル、Windows では PowerShell を使います。

</details>

## 手順が多い理由

安全のため、{productName} が受け付けるのは、<code dir="ltr">{tunnel.loopback}</code> で開いたブラウザだけです。これは常に「このコンピューター自身」を指すアドレスで、ループバックとも呼ばれます。そのため、ホストの Tailscale アドレスをブラウザにそのまま入力しても開けません。代わりに、自分のコンピューターの中継またはフォワードが、ホストが <code dir="ltr">{tunnel.loopback}</code> にあるかのように見せ、2 台の間の通信は Tailscale が運びます。ホストでは、{productName} 自身がループバックのポートで待ち受けるため、ホスト側で動かすものはありません。

## うまくいかないとき

- <strong>ページが開かない:</strong> ウィンドウのどれかが閉じられたか、コマンドが止まっています。自分のコンピューターの中継と Tailscale Serve がまだ動いていること、ホストで <code dir="ltr">{tunnel.serveStatus}</code> がホストのポートを一覧に出していることを確認してください。
- <strong>socat が「Address already in use」と表示する:</strong> そのコンピューターで、そのポートはすでに使われています。別のポートを選んでください。自分のコンピューターの場合は、ブラウザのアドレスのポートも変えます。
- <strong>ページが拒否される、または空白になる:</strong> ホストの Tailscale の名前や <code dir="ltr">100.x.y.z</code> のアドレスではなく、<code dir="ltr">{tunnel.loopback}</code> のアドレスで開いたことを確認してください。
- <strong>ページを開くと、自分のコンピューターの中継が「Connection refused」と表示する、またはページが拒否される:</strong> <strong>ブラウザアクセスを許可</strong>がオフになっているか、ほかのプログラムがブラウザ用ポートを使っているか（設定に表示されます）、ホストで {productName} が動いていません（Linux では octoboardd が動いていないか、<code dir="ltr">{commands.browserOn}</code> を実行していません）。

## 使い終わったら止める

- <strong>ブラウザを使ったコンピューターで:</strong> <kbd>Ctrl</kbd>+<kbd>C</kbd> で socat を止めます。Windows では、管理者として開いた PowerShell でフォワードを削除します。

  <Code code={tunnel.visitorForwardWindowsOff} lang="powershell" />
- <strong>ホストで:</strong> Tailscale Serve のコマンドを <kbd>Ctrl</kbd>+<kbd>C</kbd> で止めます。<code dir="ltr">{tunnel.serveStatus}</code> で、何も共有されていないことを確認します。ポートがまだ一覧に残っている場合は、<code dir="ltr">{tunnel.serveBrowserPortOff}</code> で削除します。
- <strong>Mac または Windows のホストでは、</strong>使わなくなったら<strong>ブラウザアクセスを許可</strong>をオフにします。これでブラウザ用ポートが閉じ、そのキーで開いているページはすべて切断されます。
- <strong>Linux のホストでは、</strong>使わなくなったら <code dir="ltr">{commands.browserOff}</code> を実行します。これでブラウザ用ポートが閉じ、そのキーで開いているページはすべて切断されます。
- <strong>アドレスが漏れたかもしれないときは、</strong><strong>設定 › アクセス</strong>の<strong>キーを更新</strong>で新しいキーに替えます。Linux では <code dir="ltr">{tunnel.rotate}</code> を使います。古いアドレスで開いているページは切断されます。

## セキュリティ

- <strong>アドレスはパスワードと同じ:</strong> アドレスに含まれるキーで、ホスト上の {productName} をフルコントロールでき、任意のコマンドも実行できます。キーは更新するまで有効です。ブラウザの履歴やブックマークに残り、ブラウザの同期がオンなら、ほかのデバイスにも同期されます。
- <strong>誰が届くか:</strong> ホストのポートに届いて、キーを持っている人なら誰でも届きます。ブラウザ用ポートと中継は <code dir="ltr">127.0.0.1</code> だけを待ち受けるので、ホストや自分のローカルネットワークにあるほかのデバイスからは届きません。Tailscale Serve は、アクセスルールで許される範囲で、ホストのポートを自分の tailnet からだけ届くようにします。
- <strong>他の人がサインインしないコンピューターでだけ使う:</strong> ホストや自分のコンピューターにある別のユーザーアカウントは、これらの <code dir="ltr">127.0.0.1</code> のポートに接続できます。ホストでは {productName} が動いていない間や再起動中にブラウザ用ポートを、自分のコンピューターでは中継が動いていない間にその中継のポートを奪って、ブラウザが再接続したときにキーを受け取ってしまうこともあります。[SSH で接続](../remote-connections/)する方法では、ブラウザアクセスをオフにした Linux のホストと、デスクトップアプリから使う Mac や Windows のホストにこの弱点はなく、デスクトップアプリを使う場合は自分のコンピューターにもありません。ただしブラウザを使う場合は、ブラウジングに使うコンピューターにこの弱点が残ります。そこでも SSH のフォワードが <code dir="ltr">127.0.0.1</code> のポートで待ち受けるためです。
- <strong>Funnel は使わない:</strong> Tailscale Funnel は、ポートをインターネット全体に公開してしまいます。
