Each account's usage resets on its own schedule, and sharing work out by watching them yourself is tiring and wasteful. {productName} lets the available usage decide which account a new session uses, preferring the one about to reset so usage that is about to be wiped is not wasted. With automatic switching on, a task stopped at its limit with no account to take it waits and continues once a fresh reading confirms recovery, instead of simply failing.

<Screenshot id="new-session-account-picker" alt="The account picker of the “Open session” dialog, with usage bars beside each account and one account at its limit." />

## What it does

- <strong>A new session takes the account that resets soonest.</strong> With <strong>Automatically select an account</strong> on, a new session takes the account of its agent whose weekly limit resets soonest. Resets less than 5 hours apart count as the same deadline, and among those the account whose five-hour window is already running goes first, because what is left of a running window is lost when it resets. An account used up on its five-hour window is never chosen, even when its weekly window resets soon.
- <strong>Accounts that cannot work are passed over.</strong> Automatic selection for a new session skips an account that is used up, not logged in, turned off or having its sharing changed, and falls to a used-up one only when nothing else is usable. The automatic switch never picks a used-up account. Neither compares accounts of different agents. Automatic selection tries another added agent only when the first has no usable account; the automatic switch never changes a session's agent.
- <strong>An account you pick yourself always wins.</strong> A used-up account is not refused for a new session, which would simply stop at its usage limit until the reset; it is refused only as the target of a switch or a handoff.
- <strong>A stopped task waits for a confirmed recovery.</strong> With <strong>Automatically switch accounts at the usage limit</strong> on, a session whose turn stopped on the limit, with no other account to take it, stays stopped and continues only after a fresh, successful reading of an account of its agent shows recovery: at least one account-wide window, and every one below 100% used. A reading taken before the turn failed, a failed reading, or just passing the reset time does not count. The session may continue on another account or on its original one.
- <strong>Its limits:</strong> the choice rests on the readings {productName} already holds, which it takes about every 5 minutes and again shortly after a window resets, so it can be a few minutes behind. For a new session, an account whose usage has not been read, or cannot be read, is not treated as unusable; the automatic switch does not move a session onto one. These waits are kept only while {productName} runs, and turning automatic switching off cancels them.

## How to use it

<Steps>

1. Open <strong>Settings › Agent accounts</strong> and turn on <strong>Automatically select an account</strong>. The row's description says what it does while it is on.
2. Open a new session. The <strong>account picker</strong> is already set to the account chosen for you, with each account's usage bars beside its name; pick another account or agent if you prefer.
3. Optionally turn on <strong>Start usage windows automatically</strong>. A window that has reset does not start counting until the account's next request, so its reset keeps moving later; with this on, {productName} sends one small request to start it. That counts a little toward the account's limits (see [Start usage windows automatically](../start-usage-windows/)).
4. Optionally turn on <strong>Automatically switch accounts at the usage limit</strong>, so that a session that stops at a limit is moved, or waits for a confirmed recovery (see [Account continuity](../account-continuity/)).

</Steps>

You know it works when new sessions open on the account whose usage is about to reset, and the account picker shows its bars. The account a session runs under is named when you hover the agent icon on its row.

<Aside type="note">
Opening a session with defaults and starting a session from another session follow the same choice. Resuming a conversation, handing a session off to a chosen agent and switching accounts keep what was specified; none of them changes the agent for you.
</Aside>
