The price of having several accounts is installing the same skills and plugins, and setting up the same MCP servers, again for each one. Accounts of the same agent can share this configuration: you set it up once and every account can use it. MCP servers are shared for Codex and Grok Build; Claude Code's user-level MCP servers stay with each account. The login always stays the account's own.

<Screenshot id="account-sharing-switch" alt="An account's settings dialog, with the “Share default configuration” and “Disable account” switches." />

## What it does

- <strong>A fixed list, per agent.</strong> What is shared is not chosen entry by entry. It covers the agent's settings and instruction files, its skills, plugins, commands and similar folders, and its conversation history. For Codex and Grok Build that includes the file that holds MCP servers, so a server defined there is shared too.
- <strong>What is not shared:</strong> login credentials; a Codex account's MCP sign-ins; Claude Code's <code dir="ltr">.claude.json</code>, which holds the account's identity, per-project trust and user-level MCP servers, so Claude Code's user-level MCP servers stay separate for each account; and per-machine caches and registries.
- <strong>Nothing is lost when it is turned on or off.</strong> Turning sharing on keeps a backup of every configuration entry the account had, and moves its conversations into the shared folder so earlier ones stay resumable. Turning it off restores the backups and takes the account's own sessions' conversations back; the rest of the history that was moved stays in the default account's folder.
- <strong>Its limits:</strong> the default account has no sharing switch, being the folder the others share. Sharing cannot be changed while the account has working sessions or is being logged in. Changing it ends the account's idle sessions and resumes them afterwards, and text typed into an idle session's terminal but not yet sent is lost. On Windows the computer running the daemon must allow file links, which Developer Mode does; turn it on in Windows Settings, then quit {productName} and open it again.

## Why it works this way

- <strong>Links, not copies.</strong> With sharing on, the parts of an account's folder that can be shared are replaced by links to the agent's default account's folder, so something installed once is seen by every account that shares, and a conversation is in one place whichever of those accounts runs it.
- <strong>The login stays separate.</strong> Credentials are never shared, so accounts that share still run side by side, each signed in as itself. Sharing one folder with only the credentials swapped would not work: every running session would follow each swap, and one session refreshing its login would break the stored copy of another account's.

## How to use it

<Steps>

1. Open <strong>Settings › Agent accounts</strong>, choose the agent's tab, and open the actions menu of the account you added, then <strong>Settings</strong>.
2. Turn on <strong>Share default configuration</strong>. The row's description names the default account it links to.
3. Wait for the progress bar under the row to finish. It shows how many entries have been processed. If the switch is unavailable, its tooltip says why: sessions of the account are working, the account is being logged in, or the computer cannot make file links.
4. Check that it worked: the row says the account's configuration and conversation history are linked to the default account's folder. Skills, plugins and settings you set up for the default account are now there for this account too.

</Steps>

If a change cannot be finished, for example because of a full disk, the switch keeps the position it had before and a warning mark explains what went wrong. Turning the switch again asks for the same change again.

### See each account's connectors and MCP servers

Accounts differ here even when they share, because a platform connector is connected on the platform's side, under the account's own sign-in. Choose <strong>Connectors and MCP</strong> in an account's actions menu for a read-out of that account's <strong>Platform connectors</strong> and <strong>Local MCP servers</strong>, with each one's state, and, for Codex, the means to sign in to a server and out of it. It is read each time the dialog opens, and <strong>Refresh connectors and MCP servers</strong> reads again. Grok Build's platform connectors cannot be listed.

<Screenshot id="account-connectors-mcp" alt="The “Connectors and MCP” dialog of a Codex account, with platform connectors and local MCP servers." />

<Aside type="note">
Removing an account that shares turns its sharing off first, under the same rules. Pointing an account at another folder does the same.
</Aside>
