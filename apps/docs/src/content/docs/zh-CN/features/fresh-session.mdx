上下文越满，模型表现越差、成本越高，运行已久的会话也不适合作为下一阶段工作的起点。{productName} 不替智能体做压缩，而是让你看清会话的上下文占用，在阶段交界处开一个干净的新会话。旧会话的对话记录仍然可以回看。

## 为什么这样设计

- <strong>在阶段交界处重新开始。</strong>每一轮都会把整段对话再发一次，所以上下文的大小决定了继续下去的成本。看得见占用，你就能自己选择重新开始的时机，而不是等会话变得笨重了才发觉。
- <strong>显示的是智能体自己报告的数字。</strong>这个数字是智能体对主对话最近一次请求所报告的大小：Claude Code 状态栏里的数字、Codex 的 <code dir="ltr">/status</code> 里的数字、Grok Build 页脚里的数字。回复流式输出时，{productName} 不做估算，所以数字可能比屏幕上的内容稍慢一点，智能体运行期间大约每秒刷新一次。压缩、回退或回溯之后，数字会降下来。
- <strong>它不是账单。</strong>这个数字是上下文的大小，不是累计的 token 用量，也不是费用或时长。智能体的子智能体和辅助调用不计入。
- <strong>新会话就是新会话，别无其他。</strong>{productName} 不会替你总结对话，也不会把对话带过去。先前的会话保留着它的记录，你可以读一读，再告诉新会话它需要知道什么。
- <strong>历史来自智能体的记录。</strong>它列出你和智能体说过的话（你发的消息，以及智能体对每一轮的最终回复），不包括工具调用、命令输出和模型的推理过程。如果智能体的记录已被删除或无法读取，历史会提示不可用。Grok Build 只保留压缩之前内容的摘要，所以它的历史只列出压缩之后的轮次。

有两种情况会让标记不完整：

- <strong>没有圆环。</strong>只有当智能体告诉 {productName} 它的上下文窗口有多大时，才会出现圆环；否则只显示数字。使用 Claude Code 时，启动后第一次报告之前（它随会话的第一条回复到来）是这样；另外，Claude Code 版本低于 2.0.0、受管策略设置了状态栏，或 Claude Code 根本不运行状态栏时（在未被信任的文件夹中，或设置了 <code dir="ltr">disableAllHooks</code>），也始终如此。
- <strong>没有标记。</strong>大小未知或为零时什么也不显示：会话刚启动时，以及使用 Claude Code 压缩之后、下一次请求之前。

## 如何使用

<Steps>

1. 在侧边栏的会话行、专注模式的会话卡片，或已归档会话历史的页眉中找到这个标记。它是一个灰色的小数字，例如 <strong>126.5K</strong>。窗口大小已知时，数字前的圆环表示已用的比例：50% 以内为强调色，超过 50% 为警告色，超过 80% 为危险色。
2. 把鼠标悬停在标记上，查看<strong>上下文窗口</strong>卡片：大小与窗口的对比、一条进度条、已用百分比和剩余量。
3. 会话快满时，用新会话开始下一阶段：在项目所在行点按 <strong>+</strong>（<strong>新建会话</strong>），在<strong>打开会话</strong>对话框中选好智能体和账户，然后打开。告诉新会话工作进行到了哪一步。
4. 也可以把旧会话归档：打开它的菜单，选择<strong>归档</strong>。归档会在 git 能安全处理的情况下，不经询问就移除该会话正在使用的分支和关联的工作树：停在提示符处的会话会立即归档，只有 git 拒绝移除的内容才需要确认。所以，请等新会话不再使用旧会话的分支或工作树之后，再归档旧会话。
5. 回顾时，选中已归档的会话，或从项目菜单打开<strong>查看归档</strong>。已归档会话的<strong>会话历史</strong>会代替终端显示这段对话，页眉里有同样的标记。如果你还是想接着这段对话继续，点<strong>重新打开</strong>。

</Steps>

<Screenshot id="session-history" alt="已归档会话的“会话历史”：你的消息和智能体的回复，页眉有上下文标记，底部有“重新打开”栏。" />

新会话出现在侧边栏，且智能体回复之后它的标记开始显示，就说明已经生效。读取历史不会向智能体的记录写入任何内容。
