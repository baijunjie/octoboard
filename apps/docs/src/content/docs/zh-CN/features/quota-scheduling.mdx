多个账户的额度各有各的重置周期，靠人盯着分配既累又浪费。{productName} 让可用额度来决定新会话用哪个账户，优先用快要重置的，别浪费即将清零的额度。开启自动切换后，停在限额上又没有账户可接手的任务会等待，并在新的读取确认额度恢复后继续，而不是直接失败。

<Screenshot id="new-session-account-picker" alt="“打开会话”对话框的账户选择器，每个账户旁都有用量条，其中一个账户已达上限。" />

## 为什么这样设计

- <strong>先用即将过期的额度。</strong>开启<strong>自动选择账户</strong>后，新会话会选用该智能体中每周限额最早重置的账户。相差不到 5 小时的重置视为同一个截止时间，其中 5 小时窗口已经在计时的账户优先，因为正在计时的窗口剩下的部分会在重置时作废。5 小时窗口已用完的账户不会被选中，即使它的每周窗口很快就重置。
- <strong>不能工作的账户会被跳过。</strong>为新会话自动选择账户时，会跳过已用完、未登录、已停用或正在更改共享的账户，只有在没有其他可用账户时才会选到已用完的账户；自动切换则从不选已用完的账户。两者都不会在不同智能体的账户之间比较。自动选择只有在第一个智能体没有可用账户时，才会尝试另一个已添加的智能体；自动切换从不更换会话的智能体。
- <strong>最终由你决定。</strong>你自己选的账户永远优先。已用完的账户不会拒绝新会话，新会话只会停在使用限制上，直到重置；只有把会话切换或移交到这样的账户上才会被拒绝。
- <strong>停下的任务要等到证据。</strong>开启<strong>达到使用限制时自动切换账户</strong>后，如果某个会话的轮次停在了限制上，又没有别的账户可以接手，它会一直停着，直到该智能体某个账户新读取并成功的结果显示已恢复：至少有一个账户级窗口，并且每个账户级窗口的已用比例都低于 100%。轮次失败之前的读取、失败的读取，或仅仅是过了重置时间，都不算数。会话可能在另一个账户上继续，也可能回到原来的账户。
- <strong>局限：</strong>选择依据的是 {productName} 已有的读取结果。它大约每 5 分钟读取一次，窗口重置后不久也会再读一次，所以可能晚几分钟。对新会话来说，尚未读取或读不到用量的账户不会被当作不可用；自动切换则不会把会话移到这样的账户上。这些等待只在 {productName} 运行期间保留，关闭自动切换会取消它们。

## 如何使用

<Steps>

1. 打开<strong>设置 › 智能体账户</strong>，开启<strong>自动选择账户</strong>。这一行的说明会告诉你开启后它的作用。
2. 新建一个会话。<strong>账户选择器</strong>已经设为替你选好的账户，每个账户的名字旁都有用量条；如果你更想用别的账户或智能体，可以另选。
3. 可选：开启<strong>自动启动用量窗口</strong>。窗口重置后，要等到账户的下一次请求才开始计时，下一次重置也会因此越拖越晚；开启后，{productName} 会发出一个很小的请求来启动它。这会占用账户一点点限额（见[自动启动用量窗口](../start-usage-windows/)）。
4. 可选：开启<strong>达到使用限制时自动切换账户</strong>，这样停在限制上的会话会被切换，或等待确认恢复（见[账户连续性](../account-continuity/)）。

</Steps>

新会话会在用量即将重置的账户上打开，并且账户选择器里显示它的用量条，就说明生效了。把鼠标放在会话行的智能体图标上，可以看到会话使用的账户。

<Aside type="note">
用默认设置打开会话，以及由另一个会话启动会话，都遵循同样的选择。恢复对话、移交给指定的智能体和切换账户会保留你指定的内容，其中没有一项会替你更换智能体。
</Aside>
