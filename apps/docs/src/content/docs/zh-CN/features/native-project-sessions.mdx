## 功能说明

- <strong>会话就是智能体自己的程序。</strong>{productName} 从你的 <code dir="ltr">PATH</code> 里启动 Claude Code、Codex 或 Grok Build，以项目文件夹作为工作目录，并显示它的终端。你输入的对象就是智能体本身，{productName} 自己并不是智能体。
- <strong>项目里的东西一样都不替换。</strong>智能体发现项目的指令文件、技能、钩子和权限规则的方式，和在 {productName} 之外完全一样。项目自己的 MCP 服务器会和 {productName} 的并存。项目定义了钩子、{productName} 也有自己的钩子时，两者都会运行。
- <strong>{productName} 不往你的项目或智能体的设置里写东西。</strong>它不会往项目里添加指令文件、设置文件或钩子，也不修改智能体自己的配置。它加给会话的内容（比如状态钩子和它自己的 MCP 服务器）只在这次启动时提供。少数例外都源于你选择或开启的操作：切换或共享账户，以及 Git 操作（拉取，包括自动拉取，以及切换分支、恢复改动和推送）。
- <strong>信任仍由智能体决定。</strong>{productName} 自己从不做这个决定。智能体询问是否信任某个文件夹时，只有在你已授权该项目之后，{productName} 才会代为确认，信任记录由智能体自己写入。在文件夹被信任之前，智能体会扣住项目自己的一部分配置：Grok Build 不加载项目的指令、钩子和 MCP 服务器，Claude Code 则忽略项目自己的允许规则。对于 Grok Build，{productName} 之后会把 Grok 写入的那一条信任记录带到你自己的信任存储里。
- <strong>每个项目可以有自己的智能体、账户和模型。</strong>项目设置里保存着它的默认智能体，以及按智能体分别设定的账户、模型和推理强度。项目没设置的部分，跟随它所在的控制台。不同项目的会话各在自己的文件夹里独立运行。
- <strong>可选的防护让会话只留在自己的项目里。</strong>开启<strong>会话只改自己的项目</strong>后，项目会话如果在另一个已注册的项目里修改文件或更新分支，就会被拦下，并被要求改为请那个项目的会话来做。

<Aside type="caution" title="防护的局限">
它默认关闭，只作用于项目会话，不作用于控制台会话，也不管你自己的终端。它检查的是智能体的文件编辑工具和分支更新，所以通过 shell 命令写入的文件，只有在提交时才会被发现。对文件编辑的检查只对之后启动的会话生效，对提交和分支更新的检查则立即作用于正在运行的会话。它也不会撤销留在另一个项目里未提交的改动。无法判断时，它一律放行。
</Aside>

## 如何使用

<Steps>

1. 添加项目：在控制台下选择<strong>添加项目</strong>，选择它的文件夹（也可以选父文件夹，或填 Git 地址来克隆）。{productName} 会读取这个文件夹之前用过哪个智能体，并把它作为项目的默认智能体供你选用。
2. 想细调某个项目，打开它的菜单，选择<strong>项目设置</strong>。设置它的默认智能体，以及每个智能体的会话使用的账户、模型和推理强度。

   <Screenshot id="project-launch-settings" alt="“项目设置”对话框，默认智能体和启动设置都跟随控制台。" />
3. 选择项目下的<strong>新建会话</strong>。在<strong>打开会话</strong>对话框里，智能体取决于你的选择，其次是项目的设置，再其次是控制台的默认值。然后打开。
4. 确认项目的配置已生效：用智能体自己的命令列出它的技能、钩子或 MCP 服务器。它们显示的是项目的配置，因为会话就在项目的文件夹里运行。
5. 想开启防护，打开<strong>设置 › 智能体行为</strong>，打开<strong>会话只改自己的项目</strong>。对提交和分支更新的检查立即生效，对文件编辑的检查对你之后启动的会话生效。

</Steps>

会话里的智能体显示出项目自己的指令、技能和钩子，并且（开启防护后）试图修改另一个项目的项目会话被拦下、被要求去请那个项目的会话来做，就说明成功了。
