多账户的代价是每个账户都要重复安装技能、插件和 MCP 服务器。同一智能体的账户可以共享这些配置，配置一次，所有账户都能用。MCP 服务器在 Codex 和 Grok Build 下共享；Claude Code 的用户级 MCP 服务器仍属于各个账户。登录始终是各账户自己的。

<Screenshot id="account-sharing-switch" alt="“账户设置”对话框，其中有“共享默认配置”和“停用账户”两个开关。" />

## 功能说明

- <strong>每个智能体一份固定清单。</strong>共享的内容不能逐项选择，包括智能体的设置和指令文件，技能、插件、命令等文件夹，以及它的对话历史。对 Codex 和 Grok Build，还包括存放 MCP 服务器的文件，所以在那里定义的服务器也是共享的。
- <strong>不共享的内容：</strong>登录凭据；Codex 账户的 MCP 授权；Claude Code 的 <code dir="ltr">.claude.json</code>（它保存账户的身份、各项目的信任设置和用户级 MCP 服务器，所以 Claude Code 的用户级 MCP 服务器在各账户之间保持独立）；以及与本机相关的缓存和注册表。
- <strong>开启和关闭都不会丢东西。</strong>开启共享时，账户原有的每一项配置都会留一份备份，它的对话会被移入共享文件夹，之前的对话仍可恢复。关闭共享时，备份会恢复，账户自己会话的对话也会取回；其余已移走的对话历史仍留在默认账户的文件夹里。
- <strong>局限：</strong>默认账户没有共享开关，因为它的文件夹就是其他账户共享的那个。账户有会话正在工作或正在登录时，不能更改共享。更改共享会结束该账户的空闲会话，之后再恢复它们；输入在空闲会话终端里但尚未发送的文字会丢失。在 Windows 上，运行守护进程的电脑必须允许创建文件链接，开启“开发人员模式”即可；在 Windows 设置中打开它，然后退出 {productName} 再重新打开。

## 为什么这样设计

- <strong>是链接，不是复制。</strong>开启共享后，账户文件夹中可以共享的部分会被替换为指向智能体默认账户文件夹的链接，所以装一次的东西，所有共享的账户都能看到；一段对话无论由哪个共享账户运行，都在同一个地方。
- <strong>登录仍然各自独立。</strong>凭据从不共享，所以共享配置的账户仍然可以同时运行，各自以自己的身份登录。如果干脆共用一个文件夹、只替换凭据，是行不通的：每个运行中的会话都会跟着每次替换走，而一个会话刷新登录，就会让另一个账户保存的那份登录失效。

## 如何使用

<Steps>

1. 打开<strong>设置 › 智能体账户</strong>，选择智能体的标签页，打开你添加的账户的操作菜单，再选择<strong>设置</strong>。
2. 开启<strong>共享默认配置</strong>。这一行的说明里写明了它链接到哪个默认账户。
3. 等这一行下面的进度条走完，它会显示已处理多少项。如果开关不可用，它的提示会说明原因：账户有会话正在工作、账户正在登录，或电脑无法创建文件链接。
4. 确认是否生效：这一行会说明账户的配置和对话历史已链接到默认账户的文件夹。你为默认账户设置的技能、插件和设置，现在这个账户里也有了。

</Steps>

如果更改没能完成，比如磁盘已满，开关会保持更改前的位置，并用一个警告标记说明出了什么问题。再次拨动开关，会重新请求同样的更改。

### 查看每个账户的连接器和 MCP 服务器

即使共享了配置，各账户在这方面仍有区别，因为平台连接器是在平台那边、用账户自己的登录连接的。在账户的操作菜单中选择<strong>连接器与 MCP</strong>，可以查看该账户的<strong>平台连接器</strong>和<strong>本地 MCP 服务器</strong>及各自的状态；对 Codex，还可以登录和退出某个服务器。每次打开这个对话框都会重新读取，点击<strong>刷新连接器和 MCP 服务器</strong>可以再读一次。Grok Build 的平台连接器无法列出。

<Screenshot id="account-connectors-mcp" alt="Codex 账户的“连接器与 MCP”对话框，列出平台连接器和本地 MCP 服务器。" />

<Aside type="note">
移除一个共享配置的账户时，会先按同样的规则关闭它的共享；把账户指向另一个文件夹时也一样。
</Aside>
