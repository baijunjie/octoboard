真实需求常常横跨多个项目（前端、后端、文档）。你只需把一个请求交给控制台会话，由它拆分给各项目的智能体、跟进进度、汇总报告，你从一个入口开始即可。

<Screenshot id="console-sessions-sidebar" alt="侧边栏顶部是控制台会话，它们启动的项目会话在各自的项目下，每个会话都有状态图标。" />

## 为什么这样设计

- <strong>一个入口，处理横跨项目的工作。</strong>你只需描述一次需求。控制台会话判断它属于本控制台的哪些项目，把各部分交给对应项目的智能体，之后跟进并汇总，不用你在项目之间来回转述。控制台把项目归在一起，同一个控制台里可以同时运行多个控制台会话。
- <strong>控制台会话自己不改任何项目。</strong>对项目的每一处改动，都由它在该项目里启动的会话来完成，这个会话会加载该项目自己的指令、技能和设置（见[原生项目会话](../native-project-sessions/)）。控制台会话仍然可以读取项目，并通过 {productName} 自带的工具查看会话改了什么，而不是在项目里运行 <code dir="ltr">git status</code>。
- <strong>它启动的会话就是普通的项目会话。</strong>它们显示在侧边栏各自的项目下，带一个控制台会话颜色的小圆点，你可以打开其中任何一个并直接输入（见[会话状态与介入](../session-intervention/)）。
- <strong>会话会汇报。</strong>由控制台会话启动的会话会向它发送报告，说明工作已完成、失败，还是需要你做决定。控制台会话会在自己的终端和报告面板里把结果展示给你，报告面板可以放表格、图表和表单。
- <strong>会话之间可以互通信息。</strong>任何会话都能看到其他正在运行的会话，并告诉它们一些事情。这只是信息，不是命令：会话只接受它的上级或你的安排，而且送到它那里的信息会同时抄送给它的上级。

<Aside type="caution" title="局限">
- 控制台会话只处理本控制台的项目。对于其他控制台的项目，它会请你去那里启动会话。
- 这一切都由 AI 智能体完成。{productName} 会把信息标明为“不是指令”，但模型是否照做由模型自己决定，{productName} 无法强制。
- 智能体自己的权限提示仍然有效：需要你批准的会话会停下来等你。
</Aside>

## 如何使用

<Steps>

1. 在侧边栏的控制台会话区域，选择<strong>新建控制台会话</strong>。在<strong>打开控制台会话</strong>对话框里选好智能体和账户，然后打开。

   新会话的一行会出现在<strong>控制台会话</strong>下，带有状态图标和智能体图标。
2. 在控制台会话的终端里，用自然的语言描述你的需求。知道涉及哪些项目就直接写出来，不知道的话，它会自己判断需求属于哪些项目。
3. 查看工作分派情况。它启动的会话会出现在各自的项目下；它交出去的工作还在进行时，控制台会话显示为<strong>子会话工作中</strong>。
4. 用顶栏的<strong>显示报告面板</strong>打开报告面板，控制台会话会把汇总放在那里。如果页面带有表单，填好后提交一次：你的回答会作为一条消息送回控制台会话。
5. 想直接和某个项目打交道，就在侧边栏选中它的会话并输入。想在控制台会话之外自己开一个会话，可以选择项目下的<strong>新建会话</strong>，并在对话框里把<strong>汇报给</strong>设为你想让它汇报的控制台会话。

</Steps>


控制台会话的总结出现在它的终端或报告面板里，并且它名下的会话都完成后它的状态回到静止状态，就说明成功了。

<Screenshot id="report-interactive" alt="控制台会话的报告面板，页面里有一个向用户提出的问题和若干选项。" />

### 相关设置

- 在控制台设置里，<strong>控制台会话指令</strong>可以为该控制台的控制台会话添加你自己的指令。它们优先于内置指令，但不能让控制台会话自己去改项目。
- 在<strong>设置 › 智能体行为</strong>里，<strong>自动批准新建会话请求</strong>等批准开关，决定 {productName} 对会话发来的哪些请求不再询问你直接批准。这些开关一开始都是关闭的。
