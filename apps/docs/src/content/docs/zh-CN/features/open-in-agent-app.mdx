{productName} 的核心是在你的各个项目和会话之间编排智能体。它并不想成为单个智能体最好的工作场所：Claude、Codex 这类应用在这方面做得非常出色，功能强大、体验丰富，{productName} 不想重复它们已有的东西。当你觉得接下来的任务需要更强大的应用时，可以选择在该智能体自己的应用里接着做这个会话的工作。对话会在那里继续，不必从头再来。

<Screenshot id="open-in-app-menu" alt="已中断会话的菜单：“移交”之后是“在 Claude 应用中打开”，并带有智能体的应用可能看不到此对话的提示。" />

## 为什么这样设计

- <strong>{productName} 负责编排，智能体的应用负责深入工作。</strong>各司其职，两边的好处你都能得到：在一个地方管理多个智能体和项目，某个任务值得时再用完整的应用。
- <strong>这是一座桥，不是复制。</strong>{productName} 只是请应用显示会话的对话：不复制任何内容，不改变会话，也不会停止它运行的任何东西。会话在 {productName} 中仍是已中断或已归档；之后你在 {productName} 中恢复或重新打开它时，应用不应同时写入。
- <strong>只有已停止的会话才能打开。</strong>智能体在 {productName} 中运行时，应用和 {productName} 会同时写入这段对话，所以会话还有进程时该操作是禁用的，下方显示<strong>会话运行中</strong>。请先停止会话，例如归档它。还没有对话的会话没有内容可打开，会显示<strong>尚无对话</strong>。
- <strong>在守护进程所在的电脑上发生。</strong>对于远程窗口，应用会在远程那台机器上打开，而不是在运行窗口的电脑上。该操作只在 Mac 或 Windows 电脑上提供，并且要求那里装有该智能体的应用。Grok Build 没有应用，所以永远不会出现这个操作。
- <strong>应用只读取智能体的默认目录。</strong>如果对话的最新记录存放在某个账户自己的目录中（该账户不共享默认配置），菜单项会带一行提示：<strong>智能体的应用可能看不到此对话</strong>。这只是提醒：操作仍然可用，但应用可能显示较旧的状态，或什么也看不到。

## 如何使用

<Steps>

1. 如果会话在运行，先停止它：打开它的菜单，选择<strong>归档</strong>。
2. 打开会话菜单，根据它的智能体选择<strong>在 Claude 应用中打开</strong>或<strong>在 Codex 应用中打开</strong>。在已中断的会话上，它紧跟在<strong>移交</strong>之后；在已归档的会话上，紧跟在<strong>重新打开</strong>之后。快捷键是 <strong>W</strong>。
3. 也可以从项目菜单打开<strong>查看归档</strong>，选择<strong>查看全部</strong>，把鼠标移到会话行上，点窗口图标。它是这一行按钮中的第一个，在<strong>重新打开</strong>之前。

</Steps>

<Screenshot id="open-in-app-archive" alt="归档视图中悬停时显示的一行三个按钮：第一个是“在智能体的应用中打开”（窗口图标），然后是“重新打开”和“删除”。" />

应用带着这段对话来到前台，就说明成功了。如果没有，会弹出标题为<strong>无法打开智能体的应用</strong>的提示，说明应用可能没有安装、没有启动，或没有可打开的对话。详情里有原因，之后可以重试。

应用接手对话时，{productName} 原本在等着让会话自行恢复的等待，例如等账户用量限额重置，会随之结束。
