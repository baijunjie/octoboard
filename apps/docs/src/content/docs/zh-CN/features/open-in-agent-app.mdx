{productName} 的核心是在你的各个项目和会话之间编排智能体。它并不想成为单个智能体最好的工作场所：Claude、Codex 这类应用在这方面做得非常出色，功能强大、体验丰富，{productName} 不想重复它们已有的东西。当你觉得接下来的任务需要更强大的应用时，可以选择在该智能体自己的应用里接着做这个会话的工作。对话会在那里继续，不必从头再来。

<Screenshot id="open-in-app-menu" alt="已中断会话的菜单：“移交”之后是“在 Claude 应用中打开”，并带有智能体的应用可能看不到此对话的提示。" />

## 功能说明

- <strong>这是一座桥，不是复制。</strong>{productName} 只是请应用显示会话的对话，不复制任何内容。
- <strong>尚未归档的会话会在确认后先归档。</strong>它下面的会话也一并归档。它的分支和工作树会保留，因为应用在会话的目录里工作；后台进程由你选择哪些继续运行。在应用里做完后，从归档中重新打开它，就能在这里继续。
- <strong>只在装有该智能体应用的电脑上提供。</strong>此操作支持 Claude Code 和 Codex，需要在 Mac 或 Windows 电脑上安装对应的应用。
- <strong>工作中的会话不能打开。</strong>会话在工作或在等你回应时，该操作是禁用的，下方显示<strong>会话正忙</strong>；等它开始等待指令后再操作。已锁定的会话显示<strong>会话已锁定</strong>，还没有对话的会话没有内容可打开，会显示<strong>尚无对话</strong>。
- <strong>应用只读取智能体的默认目录。</strong>如果对话的最新记录存放在某个账户自己的目录中（该账户不共享默认配置），菜单项会带一行提示：<strong>智能体的应用可能看不到此对话</strong>。这只是提醒：操作仍然可用，但应用可能显示较旧的状态，或什么也看不到。

## 为什么这样设计

- <strong>会话会先归档，和移交时一样。</strong>应用和 {productName} 不能同时写入这段对话，而已中断的会话一被选中就会恢复。
- <strong>在守护进程所在的电脑上发生。</strong>对于远程窗口，应用会在远程那台机器上打开，而不是在运行窗口的电脑上。会话的文件夹和对话都在那里。

## 如何使用

<Steps>

1. 打开会话菜单，根据它的智能体选择<strong>在 Claude 应用中打开</strong>或<strong>在 Codex 应用中打开</strong>。在已中断的会话上，它紧跟在<strong>移交</strong>之后；在已归档的会话上，紧跟在<strong>重新打开</strong>之后。快捷键是 <strong>W</strong>。
2. 如果会话还没归档，确认即可。确认框会列出一起归档的会话和它的后台进程：想让某个进程继续运行，就取消勾选。
3. 对于已归档的会话，也可以从项目菜单打开<strong>查看归档</strong>，选择<strong>查看全部</strong>，把鼠标移到会话行上，点窗口图标。它是这一行按钮中的第一个，在<strong>重新打开</strong>之前。

</Steps>

<Screenshot id="open-in-app-archive" alt="归档视图中悬停时显示的一行三个按钮：第一个是“在智能体的应用中打开”（窗口图标），然后是“重新打开”和“删除”。" />

应用带着这段对话来到前台，就说明成功了。如果没有，会弹出标题为<strong>无法打开智能体的应用</strong>的提示，说明应用可能没有安装、没有启动，或没有可打开的对话。详情里有原因，之后可以重试。如果会话的进程没能按时停下，应用不会打开，会话保持已归档：稍等片刻再试。

会话归档或应用接手对话时，{productName} 原本在等着让会话自行恢复的等待，例如等账户用量限额重置，会随之结束。
