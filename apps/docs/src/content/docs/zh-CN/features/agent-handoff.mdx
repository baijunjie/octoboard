不同的智能体各有所长，用量额度也各自独立。任务做到一半，想换一个智能体接着做（换个视角、当前智能体的用量用完、另一个模型更擅长下一步），{productName} 会把记录了任务、进度和剩余工作的移交记录交给新的智能体，你不必从头讲起。新会话接手原会话的位置，原会话被归档。

## 功能说明

- <strong>新会话读取一份移交包。</strong>它是 {productName} 根据原会话的记录生成的一个 Markdown 文件，生成过程不调用任何模型。里面有原会话的信息、它负责的分支及其状态、它拥有的会话、最新的待办列表、它的编辑改动过的文件，以及对话（你的消息和智能体的回复，不含工具输出、文件内容和推理过程）。新会话被要求先把它读完，再做其他事。
- <strong>新会话接手全部位置。</strong>它沿用原会话的项目（或控制台）、名称、所有者和角色、原会话拥有的会话、原会话负责的分支，以及置顶状态。原会话启动的进程继续运行并归新会话所有，但随智能体进程一起结束的除外，例如 Claude Code 的后台 shell。原本等着发给原会话的消息会转给新会话。
- <strong>只在你或所有者提出时才会发生。</strong>{productName} 从不自行移交会话，账户用量用完时也一样。若你开启，它可以把会话切换到同一智能体的另一个账户（见[账户连续性](../account-continuity/)）；移交则用于更换智能体。
- <strong>局限：</strong>新智能体只是读一份记录，没写下来的内容它就可能不知道。原会话的分支和工作树不会被清理，因为它们已转给新会话。没有其他可用的智能体时，<strong>移交</strong>为灰色。

## 为什么这样设计

- <strong>转移的是工作，不是对话。</strong>各智能体的对话记录无法互相接续，所以新会话不会接着原会话的对话继续，而是先读一份移交包。
- <strong>移交包是私密的。</strong>它写在 <code dir="ltr">{handoff.packageDir}</code> 下，只有所有者本人可读，因为对话里可能含有机密。

## 如何使用

<Steps>

1. 等会话处于静止状态：停在提示符处且后台没有运行的内容、已完成，或已中断。因账户达到用量上限而停下的会话也算静止。已归档的会话要先重新打开。
2. 打开会话菜单，选择<strong>移交</strong>。如果是灰色的，下方的一行小字会说明原因：<strong>会话正忙</strong>、<strong>子会话工作中</strong>（它下面的会话仍可能向它汇报）、<strong>会话已锁定</strong>或<strong>没有其他智能体</strong>。
3. 在<strong>移交会话</strong>对话框里，看一下<strong>将转移给新会话</strong>：分支、它拥有的会话，以及它在所有者之下的位置。没有任何内容需要转移时，对话框会这样说明。
4. 在<strong>移交给</strong>下选择智能体和账户。会话自己的智能体不会列出，用量已用完的账户无法选择。展开<strong>高级选项</strong>可以设置模型、推理强度和兼容性开关，初始值取自该智能体的新会话会使用的值。
5. 点<strong>移交</strong>。

</Steps>

对话框关闭、新会话被选中、原会话被归档，就说明成功了。如果工作已经转移之后才出错，标题为<strong>无法完成移交</strong>的提示会告诉你该归档或检查哪个会话。

拥有其他会话的会话，例如控制台会话或协调者，也可以移交它名下的会话。这时会先问你，对话框标题是<strong>移交会话？</strong>，你可以更改智能体、账户和设置，或点<strong>拒绝</strong>。想省掉这一问，可以在<strong>设置 › 智能体行为</strong>中开启<strong>自动批准移交</strong>。

## 沿用另一个智能体的配置

每个智能体还可以加载另一个智能体的配置，这样移交之后的会话仍然遵循你为第一个智能体写下的规则。这些<strong>兼容性</strong>开关是：Claude Code 的<strong>兼容 Codex</strong>，Codex 的<strong>兼容 Claude</strong>，Grok Build 则两者都有。它们默认关闭。

- 开启后，每次启动都会给会话另一个智能体的指令（<code dir="ltr">CLAUDE.md</code> 和规则，或 <code dir="ltr">AGENTS.md</code> 和规则）、技能、命令或自定义提示，以及 MCP 服务器，并要求它遵守那个智能体的钩子和权限。智能体把这些当作指令来执行，{productName} 不检查它如何执行。恢复的 Grok Build 会话只会带上 MCP 服务器和技能，因为它沿用首次启动时的指令。
- {productName} 只读取另一个智能体的文件，从不写入。每次启动都会重新计算，所以更改会在会话启动、恢复或被移交时生效。
- {productName} 无法安全传递的服务器会被略去，窗口里不会说明是哪些。Codex 的项目配置只在 Codex 信任的文件夹中生效。
- Grok Build 自带对 Claude Code 的支持，除非它的配置关闭了，否则默认开启；所以即使开关关着，它也可能加载 Claude Code 的配置。

要为某个智能体的所有账户设置开关，请打开<strong>设置 › 智能体账户</strong>，在该智能体的菜单中选择<strong>设置</strong>，然后在<strong>智能体设置</strong>对话框中找到开关。控制台、项目或单个会话也可以有自己的值：在<strong>高级选项</strong>中，选项会显示为<strong>同项目</strong>之类。
