有些工作是按时间表来的：每晚的检查、周一的汇总、月末的结账。定时任务会让 {productName} 在你选定的时间为你启动会话，只运行一次或按重复计划运行，并交给它一段提示词去处理，所以会话一出现就已经在工作，不用你自己去打开。

<Screenshot id="scheduled-tasks-page" alt="“定时任务”页面：侧边栏里是任务列表，旁边是所选任务的设置，上方显示它的下次运行和上次运行。" />

## 为什么这样设计

- <strong>重复的工作应该不用你动手就能开始。</strong>一个任务包含：启动什么（控制台中的控制台会话，或项目中的项目会话）、会话对话框里的启动设置（名称、智能体、账户、模型等）、必填的<strong>提示词</strong>（作为开场任务交给每个会话），以及一个计划。你没有指定的设置，每次运行时的决定方式，和你用默认设置打开会话时一样。
- <strong>计划就是人们常用的那几种，没有 cron 表达式。</strong><strong>一次</strong>、<strong>每小时</strong>（每小时的第几分钟）、<strong>每天</strong>、<strong>工作日</strong>、<strong>每周</strong>（在你勾选的星期几）、<strong>每月</strong>（在某一天；没有该日的月份在当月最后一天运行）和<strong>仅手动</strong>（自己从不运行）。
- <strong>时间按运行任务的那台电脑来算。</strong>任务按运行守护进程（{productName} 的后台程序）的那台电脑的时钟和时区运行，而不是你看的窗口所在的时区。两者不同时，页面会注明它的时间用的是哪个时区。
- <strong>一次运行就是一个你本可以自己打开的会话。</strong>它按会话对话框打开会话的方式启动，规则也相同，这个会话和你自己打开的一样属于你。项目任务还可以让它的会话向某个控制台会话汇报，就像[跨项目协作](../cross-project-work/)里那样。
- <strong>{productName} 关闭或电脑睡眠期间错过的运行，会补跑一次。</strong>守护进程启动时，每个在它未运行期间到点的已启用任务，如果最近一次错过的时间不超过 24 小时，就会为这个时间运行一次。正在运行的守护进程如果晚了两分钟以上才赶上某个时间（比如电脑睡眠之后），也按同样的方式补跑。错过多次也只会补跑一次。已停用的任务不会按计划运行，也不会补跑。
- <strong>智能体可以替你设置任务，每次变更都由你批准。</strong>控制台会话可以读取和修改它自己控制台的任务。能自己启动会话的项目会话（你自己打开的，或控制台会话启动的），只能读取和修改在它自己项目里启动会话的任务。由别的项目会话启动、只负责完成其中一项工作的会话，不能读取或修改任何任务。会话可以列出任务及其运行记录，也可以创建、修改、启用或停用、删除或运行任务；它被告知只有在你要求时才做变更。读取不需要批准。除非你开启了下文所说的自动批准，每次变更都要在一个对话框里等你回答，对话框写明是哪个会话、哪个任务、会有什么变化，会话写的提示词折叠在下面，因为那是智能体自己的话。你只能按原样批准或拒绝，不能在对话框里修改。这样的任务启动的会话仍然是你的，会向你汇报，除非任务在<strong>汇报给</strong>里指定了某个控制台会话。
- <strong>每次运行都有记录。</strong><strong>运行记录</strong>保留每个任务最近的 50 次运行：运行时间、由什么触发（<strong>按计划</strong>、<strong>补跑</strong>或<strong>立即运行</strong>）以及结果。无法启动会话的运行会记为失败，同时弹出一条系统通知，写明任务和原因；选择这条通知会打开该任务。成功启动会话的运行不会有通知：会话直接出现在侧边栏里。

<Aside type="caution" title="局限">
- 任务只在守护进程运行时才会运行，所以电脑关机或睡眠时什么都不会运行，不过错过的运行之后会按上文所述补跑；参见[阻止睡眠](../keep-awake/)。
- 如果一次运行到点时，前一次运行启动的会话还在工作，就会再启动一个会话：重叠的运行不会被跳过。
- 任务运行时，如果它使用的账户已停用、额度用完或没有登录，只有在<strong>自动选择账户</strong>开启时才会改用另一个账户；否则这次运行会因该账户的原因而失败。
- 如果任务要汇报的控制台会话在那一刻已归档、已删除或仍在启动，会话仍会启动，只是没有汇报对象，运行记录里会写明。
- 电脑的时区改变后，已经算好的下一次运行仍按旧时区的时间；之后的运行按新时区。
- 会话请求的变更会在你批准时再检查一遍。如果这期间任务已被删除或已超出该会话的范围、项目已被移除，或一次性任务的时间已过，批准就会失败，什么都不会改变。任务指定的账户在请求发出之后被停用，也是如此。应用在页面上本来就会拒绝的请求，例如提示词为空，会在询问你之前就被拒绝。请求最多等你 8 分钟。
- 任务保存在守护进程自己的数据里，不会随配置导出带走。删除控制台或移除项目，会同时删除它的任务。
</Aside>

## 如何使用

<Steps>

1. 选择左侧栏上的时钟按钮<strong>定时任务</strong>，再选择<strong>新建定时任务</strong>（侧边栏标题里的 <strong>+</strong>）。任务需要一个控制台来启动会话。
2. 在<strong>会话</strong>卡片里选择<strong>控制台</strong>；项目任务再选择<strong>项目</strong>（选<strong>无（控制台会话）</strong>则是控制台任务）。可以填一个<strong>名称</strong>，选择<strong>智能体</strong>及其账户；项目任务还可以在<strong>汇报给</strong>里选一个控制台会话。
3. 写好<strong>提示词</strong>：它会作为开场任务交给每个会话。
4. 在<strong>计划</strong>卡片里选择<strong>运行</strong>，再填写该计划需要的字段：<strong>日期和时间</strong>、<strong>每小时的第几分钟</strong>、<strong>时间</strong>、<strong>星期</strong>或<strong>每月几日</strong>。保持<strong>启用</strong>开启。
5. 选择<strong>保存</strong>。

</Steps>

<Screenshot id="scheduled-task-new" alt="新建定时任务的表单：“会话”卡片在“计划”卡片上方，下方固定着“保存”和“取消”按钮。" />

任务出现在侧边栏里，带着它的计划和距下次运行的倒计时，就说明成功了。想马上试一下，选择<strong>立即运行</strong>：无论计划如何、任务是否启用，它都会把任务运行一次，计划保持不变。行的菜单（⋮ 按钮，或右键）还提供<strong>启用</strong>或<strong>停用</strong>，以及<strong>删除</strong>：删除会停止这个任务，它已启动的会话保持不变。

想看任务做了什么，打开它的<strong>运行记录</strong>标签页。已启动的运行会链接到它的会话；失败的运行显示<strong>无法启动会话</strong>，以及带有原因的<strong>详情</strong>按钮。

<Screenshot id="scheduled-task-runs" alt="任务的“运行记录”，列出各次运行的时间、由什么触发，以及各自启动的会话。" />

想让会话来做，就用平常的话告诉它，例如每周一和周四 10:00 做一次依赖审计。会话会显示为<strong>等你回应</strong>，并打开标题为<strong>创建定时任务？</strong>的对话框。读一读那句话和任务将要保存的内容列表；会话写的提示词在折叠的<strong>会话写的提示词</strong>里。选择<strong>创建任务</strong>，或<strong>拒绝</strong>。其他变更也是这样询问的，对话框标题分别是<strong>修改定时任务？</strong>、<strong>启用定时任务？</strong>、<strong>停用定时任务？</strong>、<strong>删除定时任务？</strong>和<strong>运行定时任务？</strong>。

<Screenshot id="scheduled-task-request" alt="“创建定时任务？”对话框，写明提出请求的会话和它要创建的任务，列出任务的计划、智能体等设置，有折叠的“会话写的提示词”，以及“拒绝”和“创建任务”按钮。" />

想省掉这一问，可以在<strong>设置 › 智能体行为</strong>中开启<strong>自动批准定时任务变更</strong>。它一开始是关闭的，只有你能更改；开启后，会话的变更会立即生效，不再弹出对话框。
