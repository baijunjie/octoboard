- <strong>เซิร์ฟเวอร์:</strong> ในที่นี้คือเครื่อง Linux ที่คุณลงชื่อเข้าใช้ผ่านเครือข่าย มักเป็นเครื่องที่เช่าไว้และไม่มีหน้าจอของตัวเอง
- <strong>SSH:</strong> วิธีมาตรฐานแบบเข้ารหัสในการลงชื่อเข้าใช้เครื่องอื่นและพิมพ์คำสั่งบนเครื่องนั้น มีมาให้ใน macOS, Windows และ Linux

- <strong>ลายนิ้วมือ (host key):</strong> รหัสสั้น ๆ ที่ระบุตัว SSH ของเครื่องหนึ่ง การตรวจสอบเพียงครั้งเดียวจะบอกคุณได้ว่าเชื่อมต่อถูกเครื่อง
- <strong>ไฟล์คีย์:</strong> ไฟล์ที่ใช้ลงชื่อเข้าใช้แทนรหัสผ่าน ผู้ให้บริการเซิร์ฟเวอร์บางรายจะให้มา

## สิ่งที่คุณต้องมี

- <strong>วิธีลงชื่อเข้าใช้โฮสต์ด้วย SSH</strong> สำหรับเซิร์ฟเวอร์ Linux ผู้ให้บริการจะให้ที่อยู่และชื่อผู้ใช้ของคุณ หากต้องการตรวจสอบว่าใช้ได้ ให้เปิด Terminal (macOS) หรือ PowerShell (Windows) แล้วรันคำสั่งด้านล่างด้วยชื่อผู้ใช้และที่อยู่ของเซิร์ฟเวอร์ ครั้งแรกให้ตอบ <code dir="ltr">yes</code> เมื่อมันถามว่าจะเชื่อถือเซิร์ฟเวอร์หรือไม่

  <Code code={commands.signIn} lang="sh" />

  หากโฮสต์เป็น Mac หรือพีซี Windows คุณต้องเปิดการลงชื่อเข้าใช้ด้วย SSH ในการตั้งค่าระบบของเครื่องนั้น [ใช้คอมพิวเตอร์เครื่องอื่นเป็นโฮสต์](#ใช้คอมพิวเตอร์เครื่องอื่นเป็นโฮสต์) แสดงวิธีทำ
- <strong>สำหรับเซิร์ฟเวอร์ Linux ต้องติดตั้งและเริ่ม {productName} บนเซิร์ฟเวอร์</strong> [การติดตั้ง › เซิร์ฟเวอร์ Linux](../install/linux/) แสดงวิธีทำ โปรแกรมเซิร์ฟเวอร์ของ {productName} คือ octoboardd ซึ่งแอปเรียกว่า “ดีมอน”
- <strong>แอป {productName} บนเครื่องนี้</strong> สำหรับ macOS หรือ Windows เว้นแต่คุณจะใช้เพียงเบราว์เซอร์

## เชื่อมต่อกับเซิร์ฟเวอร์ Linux

<Steps>

1. ลงชื่อเข้าใช้เซิร์ฟเวอร์ผ่าน SSH ในฐานะผู้ใช้ที่รัน {productName} รันคำสั่งนี้ แล้วคัดลอกบรรทัดที่ขึ้นต้นด้วย <code dir="ltr">{commands.connectionScheme}</code> ซึ่งเป็นรายละเอียดการเชื่อมต่อที่บอกแอปว่าจะเชื่อมต่อที่ไหนและอย่างไร

   <Code code={commands.connection} lang="sh" />

   หากเครื่องนี้เข้าถึงเซิร์ฟเวอร์ด้วยที่อยู่หรือพอร์ต SSH ที่ต่างออกไป ให้เพิ่ม <code dir="ltr">{commands.host}</code> หรือ <code dir="ltr">{commands.sshPort}</code> ต่อท้ายคำสั่ง เพื่อให้แสดงรายละเอียดการเชื่อมต่อที่ถูกต้อง

   คิวอาร์โค้ดที่แสดงด้วยมีบรรทัดเดียวกันนี้ ตอนนี้ยังไม่มีแอปที่สแกนได้
2. ในแอป {productName} บนเครื่องนี้ ให้เปิด <strong>อุปกรณ์ระยะไกล</strong> จากแถบด้านซ้าย หรือบน macOS ให้เลือก <strong>ระยะไกล › อุปกรณ์ระยะไกล</strong> จากแถบเมนู บน Windows คุณยังเลือก <strong>อุปกรณ์ระยะไกล</strong> ได้จากเมนูระบบของหน้าต่าง หรือจากจัมป์ลิสต์ของไอคอนบนทาสก์บาร์
3. เลือก <strong>เพิ่มดีมอนระยะไกล</strong> แล้วเลือก <strong>วาง</strong> ใต้ <strong>รายละเอียดการเชื่อมต่อ</strong> เพื่อกรอกช่องต่าง ๆ
4. ใต้ <strong>การยืนยันตัวตน</strong> ให้เลือก <strong>รหัสผ่าน</strong> หากคุณลงชื่อเข้าใช้ด้วยรหัสผ่านของบัญชี ให้เลือก <strong>ไฟล์คีย์</strong> หากผู้ให้บริการเซิร์ฟเวอร์ให้ไฟล์คีย์มาแทน (มักตั้งชื่อประมาณ <code dir="ltr">id_ed25519</code> หรือลงท้ายด้วย <code dir="ltr">.pem</code>) แล้วป้อนตำแหน่งของไฟล์บนเครื่องนี้
5. เลือก <strong>บันทึก</strong> แล้วเลือก <strong>เชื่อมต่อ</strong> ป้อนรหัสผ่านหากมันถาม

   หากคุณวางรายละเอียดการเชื่อมต่อ ตัวตนของเซิร์ฟเวอร์ (ลายนิ้วมือ) จะมาพร้อมกัน และแอปจะตรวจสอบให้คุณ หากคุณพิมพ์ที่อยู่เอง แอปจะแสดงลายนิ้วมือในครั้งแรก เพื่อให้แน่ใจว่าเชื่อมต่อถูกเครื่อง ให้เทียบกับลายนิ้วมือที่คำสั่งนี้แสดงบนเซิร์ฟเวอร์ และเชื่อมต่อต่อเมื่อตรงกันเท่านั้น

## ใช้คอมพิวเตอร์เครื่องอื่นเป็นโฮสต์

คุณยังเข้าถึง Mac หรือพีซี Windows ที่รันแอป {productName} ได้ด้วย

<Steps>

1. บนคอมพิวเตอร์ที่ต้องการเข้าถึง ให้เปิด <strong>การตั้งค่า › การเข้าถึงระยะไกล</strong> ใน {productName}
2. เลือก <strong>เปิดการตั้งค่าระบบ</strong> (macOS) หรือ <strong>เปิดการตั้งค่า</strong> (Windows) ตรงนั้น แล้วเปิด <strong>การเข้าสู่ระบบระยะไกล</strong> (macOS) หรือ <strong>OpenSSH Server</strong> (Windows) ตามเส้นทางที่แถวนั้นบอก เพื่อให้คอมพิวเตอร์เครื่องนี้ยอมรับการลงชื่อเข้าใช้ด้วย SSH ขั้นตอนนี้ต้องใช้ผู้ดูแลระบบ เมื่อกลับมาที่ {productName} แถวนั้นจะแสดง <strong>เปิด</strong>
3. เปิด <strong>อนุญาตการเข้าถึงระยะไกล</strong> เลือก <strong>อนุญาต</strong> เพื่อยืนยัน และเปิด {productName} ทิ้งไว้ หากปิดแอป การเข้าถึงระยะไกลจะหยุดทำงาน
4. ที่แท็บ <strong>แอป {productName}</strong> ให้เลือก <strong>คัดลอกรายละเอียดการเชื่อมต่อ</strong> แล้วส่งไปยังคอมพิวเตอร์อีกเครื่อง เช่นทางอีเมลหรือแชต
5. บนคอมพิวเตอร์ที่คุณจะใช้ทำงาน ให้เพิ่มโฮสต์ตามขั้นตอนที่ 2 ถึง 5 ของ [เชื่อมต่อกับเซิร์ฟเวอร์ Linux](#เชื่อมต่อกับเซิร์ฟเวอร์-linux) โดยวางรายละเอียดที่ส่งมา ลงชื่อเข้าใช้ด้วยชื่อผู้ใช้และรหัสผ่านบนโฮสต์

</Steps>

คุณจะรู้ว่าสำเร็จเมื่อหน้าต่างแยกต่างหากเปิดขึ้น แสดงโปรเจ็กต์และเซสชันของโฮสต์

## จากเบราว์เซอร์

<Steps>

1. รับคำสั่ง SSH forward

   - <strong>บนโฮสต์ Mac หรือ Windows</strong> ให้ทำขั้นตอนที่ 1 ถึง 3 ของ [ใช้คอมพิวเตอร์เครื่องอื่นเป็นโฮสต์](#ใช้คอมพิวเตอร์เครื่องอื่นเป็นโฮสต์) ก่อน จากนั้นที่แท็บ <strong>เบราว์เซอร์</strong> ให้ดู <strong>ขั้นตอนที่ 1: SSH forward</strong> คลิกที่อยู่ในคำสั่งเพื่อเลือกว่าคอมพิวเตอร์อีกเครื่องจะเข้าถึงเครื่องนี้อย่างไร (หรือเลือก <strong>ป้อนที่อยู่เอง</strong> แล้วแทนที่ <code dir="ltr">{commands.server}</code> ภายหลัง) แล้วเลือก <strong>คัดลอกคำสั่งส่งต่อ</strong> และเลือก <strong>คัดลอกที่อยู่</strong> ใต้ <strong>ขั้นตอนที่ 2: ที่อยู่ของเบราว์เซอร์</strong> ด้วย
   - <strong>บนเซิร์ฟเวอร์ Linux</strong> ให้รันคำสั่งนี้บนเซิร์ฟเวอร์ มันจะแสดงที่อยู่ของเบราว์เซอร์ แล้วตามด้วยคำสั่ง SSH ที่ต้องรัน

     <Code code={commands.address} lang="sh" />

     แทนที่ <code dir="ltr">{commands.server}</code> ในคำสั่งด้วยที่อยู่ของเซิร์ฟเวอร์
2. บนคอมพิวเตอร์ที่คุณจะใช้เบราว์เซอร์ ให้รันคำสั่ง SSH ใน Terminal (macOS) หรือ PowerShell (Windows) หน้าต่างอาจถามรหัสผ่านของคุณ จากนั้นจะไม่แสดงอะไรอีก ซึ่งเป็นเรื่องปกติ เปิดทิ้งไว้ขณะทำงาน เพราะถ้าปิด เบราว์เซอร์จะตัดการเชื่อมต่อ
3. เปิดที่อยู่ของเบราว์เซอร์ ซึ่งขึ้นต้นด้วย <code dir="ltr">http://127.0.0.1:</code> ในเบราว์เซอร์ของคุณ

</Steps>

คุณจะรู้ว่าสำเร็จเมื่อ {productName} เปิดขึ้นในแท็บของเบราว์เซอร์โดยไม่ให้คุณลงชื่อเข้าใช้

เฉพาะผู้ที่เข้าถึง {productName} ผ่าน SSH forward ได้เท่านั้นที่ใช้ที่อยู่นี้ได้ โปรดเก็บเป็นความลับ เพราะคีย์ของมันควบคุมได้เต็มรูปแบบ และมันจะอยู่ในประวัติและบุ๊กมาร์กของเบราว์เซอร์ และซิงก์ไปยังอุปกรณ์อื่นของคุณหากเปิดการซิงก์ของเบราว์เซอร์

## หากใช้งานไม่ได้

- <strong>“เข้าถึงเซิร์ฟเวอร์ไม่ได้” หรือคำสั่ง SSH แจ้ง “Connection refused” หรือหมดเวลา:</strong> การลงชื่อเข้าใช้ด้วย SSH บนโฮสต์ปิดอยู่ หรือที่อยู่หรือพอร์ต SSH ไม่ถูกต้อง ตรวจสอบว่า <strong>การเข้าสู่ระบบระยะไกล</strong> หรือ <strong>OpenSSH Server</strong> เปิดอยู่ และคุณลงชื่อเข้าใช้ด้วยคำสั่ง <code dir="ltr">ssh</code> ข้างต้นได้
- <strong>“ลงชื่อเข้าใช้ไม่ได้” หรือ “Permission denied”:</strong> ชื่อผู้ใช้ รหัสผ่าน หรือไฟล์คีย์ไม่ถูกต้อง
- <strong>“คีย์โฮสต์ไม่ตรงกัน”:</strong> เครื่องที่ตอบกลับไม่ใช่เครื่องที่คุณเคยเชื่อมต่อ กรณีนี้เกิดขึ้นได้หลังติดตั้งเซิร์ฟเวอร์ใหม่ แต่ก็อาจหมายความว่ามีบางอย่างผิดปกติ อย่าดำเนินการต่อจนกว่าจะรู้สาเหตุ
- <strong>หน้าเบราว์เซอร์ไม่โหลด:</strong> หน้าต่าง SSH ถูกปิด หรือคำสั่งหยุดทำงาน ให้รันอีกครั้งแล้วโหลดหน้าใหม่

## ความปลอดภัย

- <strong>ไม่มีพอร์ตสาธารณะเพิ่ม:</strong> {productName} รับการเชื่อมต่อจากตัวโฮสต์เองเท่านั้น ดังนั้นการเชื่อมต่อจากคอมพิวเตอร์เครื่องอื่นจึงต้องลงชื่อเข้าใช้โฮสต์ผ่าน SSH ก่อน นี่คือเหตุผลที่ต้องใช้ SSH หรือใช้ [ตัวส่งต่อ](../choose-how-to-connect/) ตัวใดตัวหนึ่ง
- <strong>ตรวจสอบว่าเชื่อมต่อถูกเครื่อง:</strong> แอปจะจำ host key ซึ่งเป็นตัวตน SSH ของเครื่อง ในการเชื่อมต่อสำเร็จครั้งแรก และจะบล็อกการเชื่อมต่อพร้อมแจ้งเตือนหากตัวตนนั้นเปลี่ยนในภายหลัง
- <strong>ไม่เก็บรหัสผ่าน:</strong> หลังจากที่คุณลงชื่อเข้าใช้ครั้งแรกด้วยรหัสผ่านหรือไฟล์คีย์ของคุณเอง แอปจะสร้างคีย์ SSH แยกต่างหากให้เครื่องนี้ใช้ลงชื่อเข้าใช้ในครั้งต่อไป
- <strong>เพิกถอนการเข้าถึงของคอมพิวเตอร์เครื่องหนึ่ง:</strong> ลบรายการของคอมพิวเตอร์เครื่องนั้นออกจากรายการคีย์ SSH ที่อนุญาตของโฮสต์ (<code dir="ltr">{commands.authorizedKeys}</code> บน Linux และ macOS) คีย์นั้นจะลงชื่อเข้าใช้อีกไม่ได้ ส่วนการเชื่อมต่อที่เปิดอยู่แล้วจะอยู่ต่อจนกว่าจะสิ้นสุด

## ในหน้าต่างระยะไกล

- <strong>หนึ่งหน้าต่างต่อหนึ่งปลายทาง SSH:</strong> การเชื่อมต่อที่ใช้ชื่อผู้ใช้ โฮสต์ หรือพอร์ต SSH ต่างกันจะเปิดหน้าต่างของตัวเอง โปรเจ็กต์ เซสชัน และการแจ้งเตือนจึงไม่ปะปนกัน
- <strong>ดูสถานะของแต่ละการเชื่อมต่อ:</strong> เปิดไอคอนแถบเมนูของแอปบน macOS หรือไอคอนในพื้นที่แจ้งเตือนบน Windows เพื่อดูแท็บของแต่ละการเชื่อมต่อ
- <strong>เปิดเว็บไซต์ระยะไกลที่นี่:</strong> เมื่อเอเจนต์เริ่มเว็บไซต์บนโฮสต์ ให้คลิกลิงก์ <code dir="ltr">{commands.localhost}</code> ที่มันให้ แล้วแอปจะเปิดเว็บไซต์นั้นบนเครื่องนี้ผ่าน SSH
- <strong>เปิดไฟล์ระยะไกลที่นี่:</strong> ดูไฟล์ในหน้าต่างระยะไกล หรือดาวน์โหลดสำเนามาเปิดในแอปเริ่มต้นของเครื่องนี้สำหรับไฟล์ชนิดนั้น
- <strong>เชื่อมต่อใหม่อัตโนมัติ:</strong> หากเครือข่ายหลุด หน้าต่างจะพยายามเชื่อมต่อใหม่ต่อไปจนกว่าจะสำเร็จหรือคุณปิดหน้าต่าง
