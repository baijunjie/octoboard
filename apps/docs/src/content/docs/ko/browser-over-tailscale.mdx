SSH나 원격 데스크톱 없이, 내 Tailscale 네트워크를 통해 다른 컴퓨터의 브라우저에서 {productName}을(를) 엽니다. 호스트는 {productName}이(가) 실행되는 컴퓨터로, Mac, Windows PC 또는 octoboardd가 실행 중인 Linux 서버입니다. SSH 로그인(macOS의 원격 로그인)은 꺼 둬도 됩니다.

이 방법이 맞는지 잘 모르겠나요? [연결 방법 선택](../choose-how-to-connect/)을 보세요.

<Aside type="caution">
이 단계는 아직 완전히 시험해 보지 못했습니다. Tailscale Serve 문서와 {productName} 자체 점검을 바탕으로 작성했습니다. 중계 프로그램은 컴퓨터 한 대에서, 브라우저의 실시간 연결까지 포함해 시험해 봤지만, 두 기기 사이의 Tailscale Serve와 Windows 포워드는 아직 시험해 보지 못했습니다.
</Aside>

<strong>내 컴퓨터의 브라우저</strong> → <strong>내 컴퓨터의 중계 프로그램(127.0.0.1)</strong> ⟷ Tailscale ⟷ <strong>호스트의 중계 프로그램(127.0.0.1)</strong> → <strong>{productName}</strong>

<details>
<summary>처음이라면</summary>

- <strong>Tailscale:</strong> 기기가 어디에 있든 인터넷으로 연결해 하나의 비공개 네트워크로 묶어 주는 서비스입니다. 내 계정으로 로그인해서 씁니다.
- <strong>테일넷(tailnet):</strong> 내 Tailscale 네트워크, 즉 내 Tailscale 계정에 로그인한 기기들입니다.
- <strong>127.0.0.1(루프백):</strong> 항상 “바로 이 컴퓨터”를 뜻하는 주소입니다.
- <strong>포트:</strong> 컴퓨터 안의 프로그램 하나를 가리키는 번호로, 문 번호와 같습니다. <code dir="ltr">127.0.0.1:{commands.defaultPort}</code>은(는) 이 컴퓨터의 {commands.defaultPort}번 포트입니다.
- <strong>socat:</strong> 한 곳의 연결을 다른 곳으로 넘겨 주는 작은 무료 프로그램입니다. 여기서는 중계 프로그램 역할을 합니다.
- <strong>Tailscale Serve:</strong> 포트를 내 테일넷에만 공유하는 Tailscale 명령입니다. 비슷한 Tailscale Funnel은 전체 인터넷에 공유하므로 여기서는 절대 쓰지 마세요.
- <strong>터미널:</strong> 명령을 입력하는 창입니다. macOS에서는 터미널, Windows에서는 PowerShell입니다.

</details>

## 단계가 더 많은 이유

안전을 위해 {productName}은(는) <code dir="ltr">{tunnel.loopback}</code>에서 연 브라우저만 받습니다. 이 주소는 항상 “바로 이 컴퓨터”를 뜻합니다(루프백이라고도 합니다). 그래서 호스트의 Tailscale 주소를 브라우저에 그냥 입력할 수는 없습니다. 대신 두 컴퓨터에서 각각 작은 중계 프로그램을 실행합니다. 내 컴퓨터에서는 호스트가 <code dir="ltr">{tunnel.loopback}</code>에 있는 것처럼 보이게 하고, 호스트에서는 연결을 {productName}에 넘겨 줍니다. 두 컴퓨터 사이의 트래픽은 Tailscale이 실어 나릅니다.

## 연결되지 않을 때

- <strong>페이지가 열리지 않을 때:</strong> 창 하나를 닫았거나 그 명령이 멈췄습니다. 중계 프로그램과 Tailscale Serve가 아직 실행 중인지, 호스트에서 <code dir="ltr">{tunnel.serveStatus}</code>을(를) 실행했을 때 호스트 포트가 목록에 나오는지 확인하세요.
- <strong>socat이 “Address already in use”라고 할 때:</strong> 그 컴퓨터에서 그 포트를 이미 쓰고 있습니다. 다른 포트를 고르세요. 내 컴퓨터라면 브라우저 주소의 포트도 바꾸세요.
- <strong>페이지가 거부되거나 비어 있을 때:</strong> 호스트의 Tailscale 이름이나 <code dir="ltr">100.x.y.z</code> 주소가 아니라 <code dir="ltr">{tunnel.loopback}</code>의 주소로 열었는지 확인하세요.
- <strong>페이지를 열 때 호스트의 중계 프로그램이 “Connection refused” 또는 “No such file or directory”라고 출력할 때:</strong> <strong>원격 접근 허용</strong>이 꺼져 있거나 호스트에서 {productName}이(가) 실행 중이 아닙니다(Linux에서는 octoboardd가 실행 중이 아닙니다).

## 끄기

- <strong>브라우저를 쓴 컴퓨터에서:</strong> <kbd>Ctrl</kbd>+<kbd>C</kbd>로 socat을 멈추세요. Windows에서는 관리자 권한으로 연 PowerShell에서 포워드를 삭제하세요.

  <Code code={tunnel.visitorForwardWindowsOff} lang="powershell" />
- <strong>호스트에서:</strong> <kbd>Ctrl</kbd>+<kbd>C</kbd>로 Tailscale Serve 명령과 socat을 멈추세요. <code dir="ltr">{tunnel.serveStatus}</code>(으)로 더 이상 공유되는 것이 없는지 확인하고, 포트가 아직 목록에 있으면 <code dir="ltr">{tunnel.serveBridgeOff}</code>(으)로 지우세요(Windows에서는 <code dir="ltr">{tunnel.serveBrowserPortOff}</code>).
- <strong>Mac이나 Windows 호스트에서는</strong> 더 이상 필요 없을 때 <strong>원격 접근 허용</strong>을 끄세요. 브라우저 입구가 닫히고, 그 키로 열린 모든 페이지의 연결이 끊어집니다.
- <strong>주소가 유출됐을 수 있다면</strong> <strong>브라우저</strong> 탭의 <strong>키 교체</strong>로, Linux에서는 <code dir="ltr">{tunnel.rotate}</code>(으)로 새 키를 만드세요. 이전 주소로 열려 있던 페이지는 연결이 끊어집니다.

## 보안

- <strong>주소가 곧 비밀번호:</strong> 주소의 키는 호스트의 {productName}에 대한 전체 제어 권한을 주며, 어떤 명령이든 실행할 수 있습니다. 키를 교체하기 전까지 유효합니다. 브라우저 방문 기록과 북마크에 남으며, 브라우저 동기화를 켜 두면 다른 기기에도 동기화됩니다.
- <strong>누가 접속할 수 있나:</strong> 호스트 포트에 닿을 수 있고 키를 가진 사람은 누구든 접속할 수 있습니다. 중계 프로그램은 <code dir="ltr">127.0.0.1</code>에서만 연결을 받으므로 호스트나 내 로컬 네트워크의 다른 기기는 닿을 수 없습니다. Tailscale Serve는 접근 규칙이 허용하는 범위에서 호스트 포트를 내 테일넷에서만 닿게 합니다.
- <strong>나 혼자 로그인하는 컴퓨터에서만:</strong> 호스트나 내 컴퓨터의 다른 사용자 계정이 이 <code dir="ltr">127.0.0.1</code> 포트에 연결할 수 있고, 중계 프로그램이 실행 중이 아닐 때는 그 포트를 가로채 브라우저가 다시 연결할 때 키를 받을 수 있습니다. [SSH로 연결](../remote-connections/)하면 Mac이나 Linux 호스트에는 이 약점이 없고, 데스크톱 앱을 쓸 때는 내 컴퓨터에도 없습니다. 하지만 브라우저를 쓸 때는 브라우저를 쓰는 컴퓨터에 약점이 남습니다. 그곳에서도 SSH 포워드가 <code dir="ltr">127.0.0.1</code> 포트에서 대기하기 때문입니다.
- <strong>Funnel은 절대 금지:</strong> Tailscale Funnel은 포트를 전체 인터넷에 공개합니다.
